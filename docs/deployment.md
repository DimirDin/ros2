# Развёртывание пайплайна

## Требования

* Репозиторий на GitHub. **Публичный** — от этого зависят бесплатные
  ARM64-раннеры и анонимный доступ к образам в ghcr.io.
* Ничего больше: ни секретов, ни внешних сервисов. Публикация в GHCR идёт
  под встроенным `GITHUB_TOKEN`.

## Установка с нуля

### 1. Разрешить workflow публикацию пакетов

`Settings` → `Actions` → `General` → `Workflow permissions` →
**Read and write permissions**.

Без этого `GITHUB_TOKEN` не сможет писать в ghcr.io, и сборка упадёт на шаге
входа в реестр.

### 2. Скопировать репозиторий

```bash
git clone https://github.com/<owner>/<repo>
cd <repo>
```

### 3. Собрать базовые образы

`Actions` → `base-images` → `Run workflow`.

Первая сборка идёт долго: кеша нет, а ARM64-образы собираются под QEMU.
Ориентир — от получаса до полутора часов на комбинацию. Последующие сборки
опираются на кеш и укладываются в минуты, если менялись только верхние слои.

### 4. Собрать пакеты

`Actions` → `packages` → `Run workflow`.

Для первой проверки разумно ограничиться одной комбинацией:

* `packages`: `cuda-probe`
* `platforms`: `x86-gpu`

Это самая быстрая комбинация, и она проверяет всю цепочку целиком.

### 5. Сделать образы публичными

По умолчанию пакеты в GHCR приватные. Для каждого:
страница пакета → `Package settings` → `Change visibility` → `Public`.

Проверка:

```bash
docker pull ghcr.io/<owner>/<repo>/base-x86-gpu:latest
```

## Триггеры

| Событие | Что запускается |
|---|---|
| push в `main`, затронуты `base/**` | пересборка базовых образов |
| push в `main`, затронуты `packages/**`, `templates/**`, `src/**` | пересборка пакетов |
| push тега `v*` | сборка пакетов с версионными тегами |
| понедельник, 03:00 UTC | пересборка базовых образов |
| ручной запуск | обе, с фильтрами по пакетам, платформам и способам |

Еженедельный cron нужен потому, что базы тянут apt- и ROS-пакеты, которые
обновляются вне нашего контроля. Лучше узнать о поломке из планового прогона,
чем из чужого срочного билда.

## Подключение self-hosted раннера на Jetson

Даёт единственное, чего не дают GitHub-раннеры, — выполнение CUDA-ядер на
реальном GPU.

На устройстве:

```bash
# Docker с поддержкой NVIDIA (в JetPack входит по умолчанию)
sudo apt-get install -y nvidia-container-toolkit
sudo systemctl restart docker
docker run --rm --runtime nvidia nvcr.io/nvidia/l4t-base:r36.2.0 nvidia-smi
```

Затем `Settings` → `Actions` → `Runners` → `New self-hosted runner`, выбрать
`Linux ARM64` и выполнить предложенные команды. При настройке задать метки:

* AGX Orin с JetPack 6.2.2 → `self-hosted,jetson,jp6`
* Orin Nano с JetPack 7.2 → `self-hosted,jetson,jp7`

Метки должны совпадать с `runners.native` в `platforms.yaml`.

После регистрации запускать workflow вручную с включённым
`include_self_hosted`. По умолчанию такие job'ы исключаются из матрицы:
`runs-on` на незарегистрированный self-hosted раннер не пропускается, а
бесконечно висит в очереди — поэтому фильтрация сделана на этапе генерации
матрицы, а не через `if:`.

## Добавление платформы

Дописать запись в `platforms.yaml` и создать соответствующий
`base/<name>.Dockerfile`. Матрица подхватит её автоматически — правки в
workflow не нужны.

## Локальная отладка

Цикл через GitHub Actions слишком длинный для отладки Dockerfile. Локально:

```bash
scripts/build-local.sh base x86-gpu
scripts/build-local.sh package cuda-probe x86-gpu
```

Сборка под ARM64 на x86-машине включает QEMU автоматически. Нужен Docker с
buildx.

## Диагностика

**Вход в GHCR отклонён.** Не выставлены Read and write permissions (шаг 1).

**`docker pull` базового образа падает при сборке пакета.** Базовые образы
ещё приватные (шаг 5) либо ни разу не собирались (шаг 3).

**Кросс-сборка падает по таймауту.** Лимит job в GitHub Actions — 6 часов.
Если тяжёлый пакет в него не укладывается, соберите его на `native-arm`:
нативная ARM-компиляция без эмуляции быстрее в разы.

**`Illegal instruction` под QEMU.** Эмулятор поддерживает не все инструкции
ARM64. Обычно помогает отключить `-march=native` в `cmake_args` пакета.

**rosdep не находит ключ.** Зависимости нет в индексе rosdep. Добавьте её в
`apt_deps`, либо подтяните исходники через `vcs_file` и укажите ключ в
`rosdep_skip_keys`.
